# BUG-20260929-001 Fix Plan — Scene Instance Editor Authoring Boundary

> **For agentic workers:** Use this plan task-by-task with the repository's TDD workflow. Do not run Agent 5; it was explicitly declined by the user. This plan is not authorization to begin implementation.

**Goal:** Ensure every accepted editor mutation has an authored persistence destination, while preserving linked Scene Instance source semantics and allowing intentional per-instance edits through explicit mechanisms.

**Architecture:** Add one canonical Scene-level resolver for authored versus materialized entity origin, then make editor mutation admission use it before creating undo/dirty state. Keep source edits, instance-root edits, supported overrides, and structural per-instance edits as distinct semantics; use read-only feedback or Make Unique when an operation has no persisted representation.

**Tech Stack:** Python 3.12, Expra Scene/Level models, existing command stack, PySide6 Qt editor, protobuf document codec, pytest.

---

**Evidence / report:** [BUG-20260929-001 opposition report](../opposition/BUG-20260929-001-opposition.md). Four opposition reviews narrow the issue to the editor accepting edits to generated descendants; Agent 5 was not run per user direction, so the BugGuard review remains incomplete.

**Scope:** No source or test changes were made while writing this plan. The candidate bug is the editor's mutation/persistence mismatch, not the intentional save-time omission of generated instance descendants.

## Verified behavior to preserve

- Scene/Level authored entities and Scene Instance roots are persisted by `Project.save_document()`.
- Materialized descendants are resolved from their source and omitted from compact saves.
- Root Transform is the current persisted placement override.
- Script exposed-value overrides are stored on the owning instance component; editing the generated clone directly does not update that map.
- World descriptors are edited as World data; detailed Level entities are edited by opening the Level document.
- Play/runtime state is isolated from edit state; Stop restores the edit scene.

## Acceptance criteria

- No editor action reports a materialized-child edit as dirty/saved unless the mutation has a persistent destination in source, an authored override, or a made-unique subtree.
- Unsupported edits explain how to open the source or make the instance unique.
- Existing root placement, source editing, script override and World/Play semantics remain unchanged.
- Reparenting cannot create a saved authored entity whose parent was filtered out as generated.
- Save failure keeps the document dirty and produces a user-visible error.
