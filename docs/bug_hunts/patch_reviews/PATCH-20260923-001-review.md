## Patch summary

Add source-driven static sprite metadata and shared texture rendering to Expra.
The editor can render a canonical Pygame frame into a Tk pixel layer when all
visible textures are available, otherwise it retains the existing Tk geometry
fallback. Editor-only render target construction, pixel bridging, and collider
overlay drawing are split into dedicated UI modules to preserve the viewport
module size budget.

**Scope and verdict:** I performed a final read-only review of the current

#### Confirmed finding 1: rotated visible items are culled with unrotated bounds (P2, high confidence)

Evidence chain:

- `src/expra_engine/runtime/rendering.py:314-339` uses half the unrotated
  primitive width/height unless `context.camera.rotation` is nonzero. It does
  not include `transform.rotation` when calculating the projected AABB.
- `src/expra_engine/runtime/rendering.py:385-386` filters the canonical frame
  through that bound before any backend sees it. The editor target calls this
  at `src/expra_engine/ui/viewport_render_target.py:82-83`.
- The new editor gate correctly rejects rotated texture-free rectangles at
  `src/expra_engine/ui/editor_pixel_renderer.py:64-70`, so those items rely on
  the Tk polygon fallback. Textured rotated sprites remain eligible for the
  pixel path, but both paths are lost if culling happens first.
- The fallback's rotated polygon calculation at
  `src/expra_engine/ui/viewport.py:523-533` is correct for an item that reaches
  it; the defect is the earlier visibility test.

Reproduction with a 2x2 item at world x=6.1, rotation 45 degrees, camera width
10, and a 100x100 viewport:

```text
{'pixel_gate': True, 'visible_items': (),
 'projected_bounds': (100.99999999999999, 40.0, 120.99999999999999, 60.0)}
```

The rotated square's leftmost corner projects to x=96.857864, so it intersects
the viewport boundary even though the axis-aligned bound starts at x=101. The
same scene through `build_editor_render_target()` produced:

```text
{'target_items': (), 'camera_position': (0.0, 0.0)}
```

This is user-visible near viewport edges: a rotated static primitive or sprite
can disappear while part of its rotated visual is still on-screen. The new
static-sprite and rotated-fallback paths make this culling gap reachable; the
current focused tests only exercise centered/in-viewport items.

#### Confirmed finding 2: fractional SpriteRegion input is silently truncated (P2, high confidence)

Evidence chain:

- `src/expra_engine/core/component_schema.py:39-65` parses every tuple field
  component as `float`; `tuple_minimum` enforces bounds but not integral pixel
  coordinates.
- `src/expra_engine/ui/inspector.py:236-239,277-283` displays and submits the
  parsed tuple through `SetComponentPropertyCommand`.
- `src/expra_engine/runtime/visual_components.py:37-48` converts every region
  value with `int(item)` before constructing `SpriteRegion`. The public region
  fields are integer pixel coordinates, and the renderer passes them to
  `texture.subsurface()` at `src/expra_engine/runtime/pygame_renderer.py:287-297`.

Current command-path probe:

```text
{
  'descriptor_value': (1.5, 2.0, 3.0, 4.0),
  'stored_region': SpriteRegion(x=1, y=2, width=3, height=4),
  'serialized_region': [1, 2, 3, 4],
  'type_annotation': {'x': 'int', 'y': 'int', 'width': 'int', 'height': 'int'}
}
```

The Inspector accepts `1.5, 2, 3, 4`, records a command, and silently changes
the user's value to a different rectangle on assignment/serialization. The
negative and non-positive region checks are fixed, but fractional pixel input
needs rejection rather than truncation.

#### Confirmed finding 3: NineSlice.outset is reused as an out-of-bounds source rectangle (P2, contract path)

Evidence chain:

- `src/expra_engine/ui_model/nine_slice.py:32-47` applies `outset` when
  resolving any panel rectangle. Its documented meaning is to expand the
  resolved panel.
- `src/expra_engine/runtime/pygame_renderer.py:589-615` resolves the same
  `NineSlice` geometry once for the destination and again against
  `Rect(0, 0, texture_width, texture_height)` for source patches. It does not
  remove destination-only outset before resolving source coordinates.
- `src/expra_engine/ui/editor_pixel_renderer.py:61-79` now correctly checks
  `item.nine_slice.texture_id`, so a valid nine-slice resource can claim the
  pixel layer; the renderer then accepts the invalid source rectangles without

Current probe with a 32x32 texture and `NineSlice(Insets(2, 2, 2, 2),

nine_slice_missing_gate False

nine_slice_outset_sources [
